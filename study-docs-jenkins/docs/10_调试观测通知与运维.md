# 10. 调试、可观测性、通知与运维

## 1. 从现象到根因

Jenkins 问题先分类：

1. **未触发**：Webhook、SCM、Job 禁用、分支发现或凭据问题。
2. **排队**：Executor、Agent 标签、容量、锁或并发限制。
3. **Agent 启动失败**：镜像、Pod、网络、资源、工作目录或 Java 通道。
4. **Step 失败**：Shell 退出码、工具版本、依赖、权限、网络或业务错误。
5. **报告/通知失败**：插件、权限、格式、外部服务或 Post 条件。
6. **结果错误**：`catchError`、`unstable`、并行分支或下游传播逻辑。

先记录 Job、Build、阶段、Agent、提交 SHA 和失败 Step，避免只截图一段末尾日志。

## 2. Pipeline 日志

```groovy
options {
    timestamps()
    timeout(time: 30, unit: 'MINUTES')
}

steps {
    sh '''
        set -Eeuo pipefail
        echo "stage=build commit=$GIT_COMMIT"
        ./scripts/build.sh 2>&1 | tee build.log
    '''
}
```

- `set -e`：命令失败时退出。
- `set -u`：未定义变量失败。
- `pipefail`：管道中任意命令失败都返回非零。
- `tee`：同时保留日志，但要确保不打印 Secret。
- 给 `sh` 配置 `label`，让 Blue Ocean/Stage View 中的错误更容易定位。

不要在生产长期打开极高粒度的全局调试日志。需要时对单个 Job、插件 Logger 或一次 Build 临时打开，并在排错后恢复。

## 3. Jenkins 系统日志和日志记录器

Manage Jenkins → System Log 可以创建 Logger，按插件包名和级别查看 Controller 日志。命令行/容器环境中也可查看标准输出和日志文件。排查完删除或降低 Logger，避免日志洪泛和敏感信息泄露。

常见排查对象：

- GitHub/GitLab Branch Source：Webhook、API、分支发现、凭据。
- Kubernetes：Pod Pending、镜像拉取、ServiceAccount、节点资源。
- Credentials：凭据域、权限、ID、插件绑定。
- Pipeline CPS：序列化、挂起、Script Approval。
- Mail/Slack：DNS、TLS、认证、通知插件。

## 4. 运行上下文调试

```groovy
stage('Diagnostics') {
    steps {
        echo "node=${env.NODE_NAME} executor=${env.EXECUTOR_NUMBER}"
        echo "workspace=${pwd()} branch=${env.BRANCH_NAME ?: 'n/a'}"
        sh 'git status --short && df -h . && java -version'
    }
}
```

只输出安全字段。需要完整环境时，应先对字段做 allowlist 和脱敏，不要直接 `env`/`printenv` 全量输出。

## 5. 测试、警告和质量门禁

JUnit：

```groovy
post {
    always {
        junit testResults: 'reports/junit.xml', allowEmptyResults: false
    }
}
```

SonarQube Quality Gate：

```groovy
stage('Quality Gate') {
    steps {
        timeout(time: 10, unit: 'MINUTES') {
            waitForQualityGate abortPipeline: true
        }
    }
}
```

如果工具暂时不可用，不要默认跳过质量门禁；可以把“工具故障”和“质量失败”分别标识并通知责任人。报告保留应和构建保留策略一致。

## 6. 构建摘要

Jenkins 没有 GitHub Actions 的 `GITHUB_STEP_SUMMARY` 一比一字段。常见实现：

- `currentBuild.description`：短摘要，避免 HTML/用户输入。
- `publishHTML`：发布静态报告。
- `junit`/Coverage/Warnings：结构化报告和趋势。
- Email/Slack：发送版本、结果、URL 和下一步。
- 自定义插件或 Build Result 页面：平台统一摘要。

```groovy
script {
    currentBuild.description = "${env.BRANCH_NAME ?: 'unknown'} / ${env.GIT_COMMIT?.take(12)}"
}
```

## 7. 通知

通知应包含：Job、Build、分支/标签、提交、结果、失败阶段、构建 URL、制品 digest 和责任人。不要把完整日志、Secret 或未经转义的用户输入直接发送到 HTML/Slack。

```groovy
post {
    failure {
        slackSend(
            channel: '#ci-alerts',
            color: 'danger',
            message: "失败: ${env.JOB_NAME} #${env.BUILD_NUMBER} ${env.BUILD_URL}"
        )
    }
    success {
        echo "success: ${env.BUILD_URL}"
    }
}
```

可使用 Email Extension、Slack、Microsoft Teams、Webhook 或 PagerDuty 插件。通知插件和凭据也应最小授权；告警要去重，避免每个并行分支产生一条重复消息。

## 8. Jenkins UI、Blue Ocean 和 Stage View

- Classic UI 是最完整的管理和日志入口。
- Pipeline Stage View 适合快速查看阶段耗时和结果。
- Blue Ocean 提供更直观的 Pipeline 视图，但不应作为唯一运维入口，部分新功能和插件支持可能有限。
- 外部可观测性使用 Prometheus/JMX、OpenTelemetry、日志平台和 SIEM，关注 Queue、Executor、Agent、构建耗时、失败率、插件错误、磁盘和 JVM。

## 9. 关键指标

平台层：

- Queue 等待时间、Executor 利用率和 Agent 启动延迟。
- Controller CPU、堆、GC、线程、磁盘、HTTP 请求和插件错误。
- 构建成功率、失败原因分布、重试率、取消率和平均恢复时间。

交付层：

- Lead time、部署频率、变更失败率、回滚率。
- 从提交到测试、构建、审批、生产的阶段耗时。
- 缓存命中率、制品下载失败率、扫描门禁失败率。

## 10. 升级和灾备运维

- 升级前备份并导出插件清单，先在测试 Controller 演练。
- 保持 Jenkins、Java、插件和 Agent 镜像可回滚。
- 持久化 JENKINS_HOME，外部化制品、日志和 Secrets。
- 不把备份放在同一台机器或同一故障域。
- 定期恢复测试，验证 Job 扫描、凭据引用、Webhook、报告和发布回滚。
- 设置磁盘、队列、Agent Pending、JVM 和失败率告警。

## 11. 调试清单

- [ ] Webhook 投递成功且 Job 已发现正确分支。
- [ ] Queue 没有因 Agent 标签、Executor 或锁等待。
- [ ] Agent 工具版本、网络、权限和工作区空间足够。
- [ ] Shell 使用 `set -Eeuo pipefail` 并保留非敏感日志。
- [ ] 报告在 `post { always }` 中上传，质量门禁显式处理。
- [ ] 通知包含 URL、版本和失败上下文且不会泄露 Secret。
- [ ] 能从 Build URL、提交 SHA 和制品 digest 重建一次发布。
