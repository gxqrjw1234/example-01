# 06. 产物、报告、缓存与数据传递

## 1. 先区分四类数据

| 数据类型 | Jenkins 机制 | 生命周期 |
|---|---|---|
| 当前阶段的临时文件 | Workspace | 当前 Agent/Build，随清理消失 |
| 同一次 Pipeline 的临时跨 Agent 文件 | `stash` / `unstash` | 当前 Build，适合小型临时文件 |
| 可下载的构建产物 | `archiveArtifacts` 或 Artifact Manager | 按保留策略长期保存 |
| 测试/质量报告 | `junit`、Coverage、Warnings、HTML Publisher | 展示和趋势分析，通常来自 XML/HTML |
| 依赖缓存 | 工具缓存、Docker 层缓存、外部缓存 | 加速用途，不能替代正式产物 |
| 跨 Job 产物 | Copy Artifact、制品库、对象存储 | 由版本/digest 绑定，独立于工作区 |

GitHub Actions 的 `needs` 只表达依赖、Job outputs 传字符串、Artifact 传文件；Jenkins 也应明确区分顺序、字符串、文件和可发布制品。

## 2. `stash` / `unstash`

```groovy
stage('Build') {
    steps {
        sh './scripts/build.sh'
        stash name: 'web-dist', includes: 'dist/**', useDefaultExcludes: false
    }
}
stage('Publish') {
    agent { label 'release' }
    steps {
        deleteDir()
        unstash 'web-dist'
        sh './scripts/publish.sh dist'
    }
}
```

适用场景：同一次 Build 在不同 Agent 之间传递少量文件。注意：

- `stash` 默认保存在 Jenkins Controller 或配置的 Artifact Manager，频繁传大文件会增加压力。
- 大型产物应上传 Nexus/Artifactory/Azure Blob/S3/Registry 等外部制品库。
- `preserveStashes()` 只适合有限的重启场景，不是长期归档。
- `stash` 名称在一个 Build 内必须唯一，发布文件应包含版本和校验值。

## 3. `archiveArtifacts`

```groovy
post {
    success {
        archiveArtifacts(
            artifacts: 'dist/**,checksums.txt',
            fingerprint: true,
            onlyIfSuccessful: true,
            allowEmptyArchive: false
        )
    }
}
```

`fingerprint: true` 可帮助追踪文件在哪些构建中使用。归档规则：

- 发布包、SBOM、校验和等正式构建结果归档或上传制品库。
- 日志和测试报告按需求保留，不要无限增长。
- `allowEmptyArchive: true` 只用于确实允许没有文件的路径；重要产物为空应让构建失败。
- 归档前验证路径，避免把 `.env`、私钥、工作区临时文件打包。

## 4. 测试报告和质量报告

JUnit XML：

```groovy
post {
    always {
        junit testResults: 'reports/junit/**/*.xml', allowEmptyResults: false
    }
}
```

代码覆盖率、静态分析和警告通常由对应插件读取报告，例如 Cobertura、JaCoCo、Coverage、Warnings Next Generation、HTML Publisher 或 SonarQube Scanner。报告文件和构建状态要分开处理：报告上传可以 `always`，质量门禁应明确让 Build 失败或变为 `UNSTABLE`。

HTML 报告：

```groovy
publishHTML(target: [
    allowMissing: false,
    alwaysLinkToLastBuild: false,
    keepAll: true,
    reportDir: 'coverage/html',
    reportFiles: 'index.html',
    reportName: 'Coverage Report'
])
```

对用户生成的 HTML 要考虑脚本和内容注入；限制访问权限，避免把不可信内容直接当作 Jenkins UI 的可信页面。

## 5. 字符串和元数据传递

同一 Pipeline：

```groovy
script {
    def imageTag = sh(
        script: 'git rev-parse --short=12 HEAD',
        returnStdout: true
    ).trim()
    env.IMAGE_TAG = imageTag
}
```

更清晰的做法是让函数返回 `Map` 或写入受控的 metadata 文件：

```groovy
writeFile file: 'build-metadata.properties', text: "IMAGE_TAG=${env.GIT_COMMIT}\n"
archiveArtifacts artifacts: 'build-metadata.properties', fingerprint: true
```

不要把可执行 Shell 片段、Secret 或未经校验的用户输入作为“输出”传递。版本、digest、URL、环境名等字符串应有格式验证。

## 6. Job 之间传文件

Copy Artifact 插件示例：

```groovy
copyArtifacts(
    projectName: 'service-build',
    selector: specific(params.UPSTREAM_BUILD),
    filter: 'dist/**,build-metadata.properties',
    fingerprintArtifacts: true
)
```

前置条件：上游构建启用归档、下游有读取权限、选择器明确指向正确的 Build。不要使用“last successful”部署生产，因为新构建可能改变它；生产应传入不可变 Build Number、镜像 digest 或制品坐标。

外部制品库的推荐数据：

```text
artifact = service-a
version  = 1.4.2
commit   = <full sha>
digest   = sha256:<digest>
provenance = <build url>
```

部署 Job 只接受上述坐标，不重新构建，也不从“当前工作区”猜测要部署的版本。

## 7. 缓存

缓存用于加速而非传递业务结果：

- Maven/Gradle：`~/.m2`、Gradle cache，按依赖锁文件和工具版本分区。
- npm/pip：本地缓存目录或外部缓存服务。
- Docker：BuildKit registry cache，注意缓存投毒和权限。
- Kubernetes 动态 Agent：通过外部缓存或预构建工具镜像降低冷启动。

缓存键至少包含操作系统、架构、工具版本和依赖锁文件哈希。缓存命中不能保证内容可信，发布流程仍应从受信任制品库拉取正式产物。

## 8. 日志和调试产物

```groovy
post {
    failure {
        archiveArtifacts artifacts: 'logs/**/*.log,debug/**', allowEmptyArchive: true
    }
    always {
        junit testResults: 'reports/**/*.xml', allowEmptyResults: true
    }
}
```

只上传脱敏后的日志。使用 `tee`、Shell `set -o pipefail` 和明确退出码保留错误上下文：

```groovy
sh '''
    set -Eeuo pipefail
    ./scripts/test.sh 2>&1 | tee reports/test.log
'''
```

## 9. 制品保留和清理

- Job 级别设置 `buildDiscarder`，限制构建和归档数量。
- 外部制品库配置生命周期策略，但生产版本和合规证据单独保留。
- 临时 Workspace 在 `post { cleanup { deleteDir() } }` 清理。
- 不用 Workspace 作为跨 Build 的共享存储；并行 Build 可能互相覆盖。
- 迁移 Artifact Manager 前测试大文件、失败重试、权限和恢复。
