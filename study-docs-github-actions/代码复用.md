关于 **GitHub Actions 减少重复代码** 的核心方法，提取出的最核心区别与最简单的理解示例如下：

---

### 一图读懂：两种重用方式的区别

| 机制 | YAML 定位点 & 别名 (`&` / `*`) | 可重用工作流 (`uses`) |
| --- | --- | --- |
| **重用范围** | **单文件内**（同一个 `.yml` 文件里） | **跨文件/跨仓库**（不同 `.yml` 之间） |
| **比喻** | 复制粘贴宏 / 快捷方式 | 调用外部封装好的函数/子程序 |

---

### 最简单的例子

#### 1. YAML 定位点与别名：单文件内的“复制粘贴”

**场景**：在同一个工作流文件中，`job1` 和 `job2` 需要用到完全相同的环境变量，不用重复写两遍。

```yaml
jobs:
  job1:
    env: &my_env  # 1. 用 & 定义锚点（把这段配置存为变量 my_env）
      NODE_ENV: production
      CITY: Singapore
    steps:
      - run: echo "Job 1"

  job2:
    env: *my_env  # 2. 用 * 调用别名（直接把上面的配置搬过来）
    steps:
      - run: echo "Job 2"

```

---

#### 2. 可重用工作流：跨文件的“函数调用”

**场景**：你写好了一个专用的部署脚本（子工作流），其他任何项目/工作流（主工作流）只需要传参并直接调用它。

**被调用的工作流**（类似于写一个函数 `deploy.yml`）：

```yaml
# .github/workflows/deploy.yml
name: Deploy Engine
on:
  workflow_call: # 标记为可被其他工作流调用
    inputs:
      target_env:
        required: true
        type: string

jobs:
  run-deploy:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploying to ${{ inputs.target_env }}"

```

**调用方工作流**（类似于在主程序中调用函数 `main.yml`）：

```yaml
# .github/workflows/main.yml
jobs:
  call-deploy-job:
    # 直接通过 uses 路径调用上面的子工作流，并传入参数
    uses: ./.github/workflows/deploy.yml
    with:
      target_env: 'production'

```
