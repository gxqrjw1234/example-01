# GitHub Actions 调试方法速查

## 1. 开启调试日志

### 1.1 Step 调试日志（最常用）

在仓库 Settings → Secrets and variables → Actions 中添加 secret：

| Secret 名称 | 值 | 效果 |
|---|---|---|
| `ACTIONS_STEP_DEBUG` | `true` | 开启每个 step 的详细调试日志 |
| `ACTIONS_RUNNER_DEBUG` | `true` | 开启 runner 诊断日志（runner 级别） |

两者可同时开启。日志会出现在每个 step 的展开日志里，带有 `##[debug]` 前缀。

### 1.2 在 workflow 中临时开启（不修改 secret）

```yaml
jobs:
  debug-job:
    runs-on: ubuntu-latest
    env:
      ACTIONS_STEP_DEBUG: true
    steps:
      - run: echo "调试模式已开启"
```

## 2. 工作流命令打印调试信息

### 2.1 ::debug:: 命令

```yaml
- name: Debug message
  run: echo "::debug::当前变量值 = $MY_VAR"
```

> 只有开启 `ACTIONS_STEP_DEBUG=true` 时才显示，否则静默忽略。

### 2.2 直接 echo 打印

```yaml
- name: Print variables
  run: |
    echo "APP_VERSION=$APP_VERSION"
    echo "GITHUB_REF=$GITHUB_REF"
    echo "GITHUB_SHA=$GITHUB_SHA"
    echo "RUNNER_OS=$RUNNER_OS"
```

### 2.3 toJson 打印完整上下文

```yaml
- name: Dump github context
  run: echo '${{ toJson(github) }}'

- name: Dump env context
  run: echo '${{ toJson(env) }}'

- name: Dump job context
  run: echo '${{ toJson(job) }}'

- name: Dump runner context
  run: echo '${{ toJson(runner) }}'

- name: Dump steps context
  run: echo '${{ toJson(steps) }}'
```

> `secrets` 上下文不能用 `toJson` 打印，会被屏蔽。

## 3. 打印环境变量和文件系统

```yaml
- name: Print all env vars
  run: env | sort

- name: Print PATH
  run: echo "$PATH"

- name: List workspace files
  run: ls -la $GITHUB_WORKSPACE

- name: Show disk usage
  run: df -h

- name: Show current user
  run: whoami && id
```

## 4. 条件断点：失败时暂停（tmate SSH 调试）

使用 [tmate](https://github.com/mxschmitt/action-tmate) Action 在 step 失败时开启 SSH 会话，直接登录 runner 交互排查。

```yaml
- name: Setup tmate session on failure
  if: failure()
  uses: mxschmitt/action-tmate@v3
  with:
    limit-access-to-actor: true  # 只允许触发者的 GitHub 公钥登录
```

也可以无条件暂停（用于主动调试）：

```yaml
- name: Setup tmate session
  uses: mxschmitt/action-tmate@v3
```

> Runner 会打印 SSH 连接命令到日志，连接后可直接在 runner 上执行命令。会话超时后 job 继续运行。

## 5. step 结果检查

### 5.1 检查上一步是否失败

```yaml
steps:
  - name: Build
    id: build
    run: python build.py

  - name: Check build result
    run: |
      echo "outcome: ${{ steps.build.outcome }}"
      echo "conclusion: ${{ steps.build.conclusion }}"
```

| 字段 | 说明 | 可能值 |
|---|---|---|
| `outcome` | 未受 `continue-on-error` 影响的原始结果 | `success` / `failure` / `cancelled` / `skipped` |
| `conclusion` | 受 `continue-on-error` 影响后的最终结果 | 同上 |

### 5.2 continue-on-error 继续执行并捕获失败

```yaml
- name: Lint
  id: lint
  run: python -m flake8 src/
  continue-on-error: true

- name: Report lint result
  run: |
    if [ "${{ steps.lint.outcome }}" == "failure" ]; then
      echo "::warning::lint 检查失败，但继续构建"
    fi
```

## 6. job 状态函数

在 `if` 条件中使用状态函数控制调试步骤执行：

```yaml
steps:
  - name: Always run (包括取消)
    if: always()
    run: echo "无论成功失败都执行"

  - name: Run on failure
    if: failure()
    run: echo "::error::job 执行失败"

  - name: Run on success
    if: success()
    run: echo "job 执行成功"

  - name: Run on cancel
    if: cancelled()
    run: echo "job 被取消"
```

## 7. 上传调试产物（Artifact）

将日志、测试报告、构建输出上传为 Artifact，在 Actions 运行页面下载查看：

```yaml
- name: Upload debug logs
  if: failure()
  uses: actions/upload-artifact@v4
  with:
    name: debug-logs
    path: |
      logs/
      *.log
    retention-days: 7
```

上传测试报告示例：

```yaml
- name: Run tests
  run: python -m pytest --tb=long --junit-xml=test-results.xml

- name: Upload test results
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: test-results
    path: test-results.xml
```

## 8. 作业摘要（Job Summary）

将关键调试信息写入摘要页，无需进入日志即可查看：

```yaml
- name: Write debug summary
  if: always()
  run: |
    echo "## 调试信息" >> $GITHUB_STEP_SUMMARY
    echo "| 项目 | 值 |" >> $GITHUB_STEP_SUMMARY
    echo "|---|---|" >> $GITHUB_STEP_SUMMARY
    echo "| 分支 | $GITHUB_REF_NAME |" >> $GITHUB_STEP_SUMMARY
    echo "| 提交 SHA | $GITHUB_SHA |" >> $GITHUB_STEP_SUMMARY
    echo "| 触发人 | $GITHUB_ACTOR |" >> $GITHUB_STEP_SUMMARY
    echo "| Runner OS | $RUNNER_OS |" >> $GITHUB_STEP_SUMMARY
```

## 9. 重新运行失败的 job

在 GitHub Actions 运行页面：

- **Re-run failed jobs**：只重跑失败的 job，保留成功 job 的结果
- **Re-run all jobs**：重跑整个 workflow
- **Enable debug logging**：重跑时勾选此选项，等同于临时开启 `ACTIONS_STEP_DEBUG=true`，无需修改 secret

> "Enable debug logging" 是最快速的一次性调试方式，不影响仓库配置。

## 10. 本地调试：act 工具

[act](https://github.com/nektos/act) 可在本地模拟运行 GitHub Actions workflow，无需每次 push 到 GitHub。

```bash
# 安装（macOS）
brew install act

# 运行默认 push 事件
act push

# 运行指定 workflow
act -W .github/workflows/ci.yml

# 运行指定 job
act -j test

# 列出所有可用 job
act --list

# 传入 secret
act push -s MY_SECRET=value

# 使用较小的 runner 镜像（加快速度）
act push -P ubuntu-latest=catthehacker/ubuntu:act-latest
```

> act 不能完全模拟所有 GitHub 功能（如 Environments、部分 GITHUB_TOKEN 权限），复杂场景仍需在 GitHub 上验证。

## 12. GitHub CLI 调试命令

`gh` CLI 可在终端直接查看、追踪和重跑 workflow，无需打开浏览器。

```bash
# 列出最近的 workflow 运行记录
gh run list

# 查看指定 run 的详情（含各 job 状态）
gh run view <run-id>

# 实时监控正在运行的 workflow
gh run watch <run-id>

# 查看某次 run 的完整日志
gh run view <run-id> --log

# 只查看失败 step 的日志
gh run view <run-id> --log-failed

# 重新运行失败的 job（等同于页面上的 Re-run failed jobs）
gh run rerun <run-id> --failed

# 重新运行并开启调试日志
gh run rerun <run-id> --failed --debug

# 下载 artifact
gh run download <run-id>

# 手动触发 workflow（workflow_dispatch）
gh workflow run ci.yml --ref main

# 列出所有 workflow
gh workflow list

# 查看指定 workflow 的摘要
gh workflow view ci.yml

# 查看指定 workflow 的运行历史
gh run list -w ci.yml
```

最实用的调试组合：

```bash
# 1. 找到失败的 run id
gh run list --status failure

# 2. 查看失败日志
gh run view <run-id> --log-failed

# 3. 带调试日志重跑
gh run rerun <run-id> --failed --debug
```

## 13. 调试方法选择建议

| 场景 | 推荐方法 |
|---|---|
| 快速查看某次失败原因 | Re-run 时勾选 Enable debug logging |
| 长期开启详细日志 | 添加 `ACTIONS_STEP_DEBUG` secret |
| 打印上下文对象全部字段 | `toJson(github)` / `toJson(env)` 等 |
| 交互式登录 runner 排查 | tmate Action |
| 保留失败时的文件/日志 | `upload-artifact` + `if: failure()` |
| 本地快速验证 workflow 语法 | act 工具 |
| 跨步骤追踪变量传递 | 打印 `steps.id.outputs.*` 和 `steps.id.outcome` |
| 在摘要页展示关键信息 | `GITHUB_STEP_SUMMARY` |
| 终端查看日志和重跑 | `gh run view --log-failed` / `gh run rerun --debug` |
